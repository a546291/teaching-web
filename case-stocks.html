如何做的？

這是什麼？

兩種資料，兩種處理方式

這個表格背後其實是兩種完全不同性質的資料，分開處理：

產業分類、細分類、主要產品（含比例）——這是公司自己在財報、法說會揭露的資訊，證交所、櫃買中心的公開資料 API 查不到這幾欄，只能靠人工讀資料整理。這部分我自己維護在一份 JSON 檔裡，之後要新增或更新個股就手動改這份檔案。

股價——這是每天都會過期的資料，原本在 Excel 裡是貼上去就固定不動，現在改成頁面載入時去讀一份「每個交易日收盤後自動更新」的股價快照，不用我自己每天手動貼。

🧭
原則：沒有揭露明確比例的產品欄位，不會自己編數字。 表格裡看到「未揭露細項比例」，代表這家公司沒有公開拆分產品線占比，就誠實寫「未揭露」，不會用 AI 幫忙腦補一個聽起來合理的百分比。
優點與限制

什麼情況適合？什麼情況不適合？

✦ 適合的地方

  • 可以依產業分類篩選，快速看某個產業有哪些股票
  • 可以依股價排序，一眼看出區間內比較貴／便宜的個股
  • 股價每個交易日收盤後自動更新，不用手動維護
  • 主要產品說明白話、不誇大，沒有明確比例就照實寫「未揭露」
  • 純靜態網頁，沒有後端伺服器，資安風險單純
  • 資料來源公開透明：股價來自證交所／櫃買中心官方 API

△ 需要注意的地方

  • 只收錄 46 檔自己關注的股票，不是全市場選股工具
  • 股價是「收盤後」的資料，盤中看到的是前一交易日收盤價，不是即時報價
  • 產業分類、主要產品是人工整理，不會隨公司最新財報自動更新
  • TWSE／TPEx 官方 API 若當天異常，股價欄位會顯示暫時無法取得，不會顯示假數字

用了哪些工具？

純前端 + 一個排程腳本

純 HTML/JS（表格篩選、排序、上色）
TWSE OpenAPI（上市股票收盤價）
TPEx OpenAPI（上櫃股票收盤價）
GitHub Actions（排程抓價、自動 commit）
GitHub Pages（純靜態網站託管）
🤔
為什麼不是「打開頁面當下直接抓報價」？ 實測過 TWSE、TPEx 主要用到的官方 API 都沒有開放瀏覽器端的 CORS 存取，靜態網站的 JavaScript 沒辦法在使用者打開頁面的當下直接跟它們要資料。所以改成用 GitHub Actions 這個「排程機器人」，收盤後統一抓一次、整理好存成一份 JSON 檔，頁面再去讀這份同一個網站底下的檔案，就沒有這個限制了。
怎麼運作的？

從兩個官方 API，到頁面上的一列資料

如果你也想幫自己整理的股票清單做類似的事，流程大致是這樣：

並自動 commit

頁面載入時
同源讀取兩份 JSON
1

先手動整理分類資料

每檔股票一筆記錄，只放人工才能判斷的欄位：

{ "industry": "PCB/載板", "subcategory": "ABF/BT載板", "name": "欣興", "code": "3037", "products": "ABF/BT載板（用於CPU/GPU/伺服器），未揭露細項比例" }
股價欄位完全不放在這份檔案裡，避免跟自動抓取的資料互相打架、變成兩份互相矛盾的股價。
2

寫一支腳本，把兩個交易所的格式對齊

上市股票用證交所「個股日成交資訊」逐檔查詢（收盤價在回傳資料每列的第 7 欄，日期是民國年格式 115/08/13）；上櫃股票用 TPEx 整批查詢，欄位叫 Close、漲跌欄位還帶正負號字串。腳本把兩邊都轉成同一個 schema：

# scripts/update_prices.py 節錄 { "code": { "price": 981.0, "change": 8.0, "market": "TWSE" // 或 "TPEx" } }
3

用 GitHub Actions 排程執行，收盤後才動作

平日台灣時間 14:00 觸發一次，只抓這 46 檔需要的代碼。如果抓到的交易日跟現有檔案一樣（代表當天休市），就不會產生一次沒有意義的 commit。

GitHub Actions 執行紀錄截圖（待補）
4

頁面載入時合併兩份 JSON

頁面本身完全是靜態檔案，載入時用 fetch() 讀 stocks.json（分類資料）和 prices.json（股價快照），依代碼合併後渲染成下面的表格。

🎉
整個過程沒有任何一段是「常駐後端伺服器」——只有一支排程時才執行、執行完就結束的腳本，跟一個純靜態網頁。
遇到問題？

常見疑問

股價為什麼不是即時報價？

因為 TWSE、TPEx 這兩個官方 API 不開放瀏覽器直接跨網域讀取，純靜態網站沒辦法在打開頁面當下即時打 API。改成 GitHub Actions 收盤後排程抓一次收盤價，頁面上會清楚標示「資料更新於某年某月某日」，盤中看到的就是前一個交易日的收盤價。

為什麼有些股票的主要產品有寫百分比，有些沒有？

只有公司自己在財報或法說會明確揭露產品線占比時，才會寫出百分比；沒有揭露的一律寫「未揭露細項比例」，不會自己估算或編數字。

要怎麼新增或更新一檔股票？

在 stocks.json 手動加一筆（產業、細分類、名稱、代碼、主要產品），存檔推上去就好。股價不用另外設定，只要代碼存在於 TWSE 或 TPEx，下一次排程執行就會自動抓到。

如果某天 TWSE 或 TPEx 的 API 掛了怎麼辦？

腳本抓不到資料就不會覆寫，頁面會保留上一次成功抓到的快照，並繼續顯示原本的更新時間；如果某一檔代碼查無資料，股價欄位會顯示「暫時無法取得」，不會顯示 0 或用舊資料冒充成當天資料。

這是投資建議嗎？

不是。這只是我自己整理來省麻煩的筆記工具，收錄的股票、分類方式都是主觀判斷，實際投資決策請自己做功課、自行承擔風險。

資安確認

這個工具安全嗎？

🔒
純靜態網頁，沒有後端伺服器、沒有資料庫、沒有任何金鑰。 TWSE、TPEx 這兩個官方 OpenAPI 都不需要申請、不需要 API Key。
✓ 無任何硬編碼 API Key／帳號密碼（TWSE、TPEx OpenAPI 免金鑰、免申請）
✓ 沒有常駐後端伺服器，不涉及 debug 模式或 host 綁定風險
✓ 沒有資料庫，不涉及 SQL 注入或明碼儲存使用者資料的問題
✓ 前端渲染股票資料一律用 textContent 寫入，不使用 innerHTML 插入資料
✓ GitHub Actions 只使用內建、範圍限定在本 repo 的 GITHUB_TOKEN，沒有使用個人存取權杖
✓ 股價、產業分類、主要產品皆為公開資訊，不涉及任何個資或隱私資料
✓ commit 歷史與程式碼中無真實金鑰
