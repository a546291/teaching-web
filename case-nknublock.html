NKNUBLOCK
學生作品自動批改

讓程式幫你逐一開啟每位學生的 Scratch 作品，自動測試搖桿、聲音、燈光是否正常運作，截圖存證，一鍵匯出 Excel 成績單。

Python Flask Playwright 瀏覽器自動化 NKNUBLOCK 模擬器 SQLite 成績記錄 Excel 匯出
🎯
這個工具是為資訊科老師設計的。 如果你的課程使用 NKNUBLOCK 讓學生設計 Scratch 作品，並且每次批改都要一個個手動開啟測試，這個工具能大幅節省你的時間。

如果你還不確定 NKNUBLOCK 是什麼，可以先跳過這個案例，從其他比較入門的案例開始。
這是什麼？

讓程式代替你執行每一份作品

NKNUBLOCK 是一個在瀏覽器裡執行的 Scratch 平台，讓學生可以用 Scratch 積木控制模擬的硬體——搖桿、蜂鳴器、LED 燈條、8x8 點陣顯示器等等。

問題是，批改這類作品非常花時間。你需要逐一打開每位學生的 .sb3 檔案、點綠旗執行、觀察搖桿動了嗎、燈亮了嗎、分數有沒有增加……一個班 30 人，每人測試 2–3 分鐘，就要花掉一個多小時。

這個工具做的事情很簡單：把你要做的那些動作，讓程式自動做一遍。

✨
全程不需要真實硬體。 系統使用 NKNUBLOCK 的模擬模式，搖桿訊號由程式注入，不需要連接任何 Arduino 或實體裝置。

評什麼？怎麼評？

六個評分項目，自動判定

系統根據教具的功能需求，自動偵測下列六個項目，每項顯示 OK、L（部分完成）、或 —（未觸發）：

評分項目 分數 判定方式
搖桿 80 分 強制注入搖桿訊號，若精靈 X 座標移動超過 5px → OK
分數變數 +3 分 Scratch 的「分數」變數在 30 秒內有增加 → OK
倒數變數 +3 分 「倒數時間」變數在 30 秒內有減少 → OK
聲音（蜂鳴器） +2 分 蜂鳴器積木被呼叫到 → OK
燈光（LED 燈條） +2 分 / L=+1 分 燈條亮了又滅 → OK；只亮不滅 → L（部分）
8×8 點陣 +2 分 矩陣顯示數字「1」的圖案 → OK
📋
滿分 92 分（搖桿 80 + 其他各項合計 12）。 分數比例可依需求自行調整程式碼。搖桿佔最高分，是因為它是這系列教具的核心操控方式。
優點與限制

什麼情況適合？什麼情況不適合？

✦ 適合的地方

  • 一個班 30 份作品，約 15–20 分鐘全部跑完
  • 不需要連接任何實體硬體，純模擬執行
  • 每份作品都有截圖存檔，方便日後查閱或申訴
  • 匯出 Excel 含班級座號、成績，可直接貼到成績系統
  • 學生資料完全留在自己電腦，不上傳任何雲端
  • 程式碼完全公開，可自行調整評分項目與分數

△ 需要注意的地方

  • 僅限 Windows 系統（Playwright 以有介面模式執行 Chromium）
  • 需要先安裝 Python，對初學者有一定門檻
  • 批改前 NKNUBLOCK 必須已在本機啟動
  • 第一次需要設定搖桿座標（之後固定）
  • 偵測項目固定，若換新教具型號需調整積木關鍵字
用了哪些技術？

這個系統的組成

Python Flask（後端 Web 介面）
Playwright（瀏覽器自動化）
SQLite（成績記錄）
openpyxl（Excel 匯出）
🤔
不懂這些名詞沒關係。 簡單說：Playwright 是一個會自動操作瀏覽器的程式，等於讓電腦模仿你打開瀏覽器、點綠旗、等待、截圖這些動作。Flask 讓你用瀏覽器介面設定這些動作，不需要在命令列輸入複雜的指令。
怎麼開始？

三個頁面，完成一次批改

第一次設定約需 30 分鐘，主要花在安裝 Python 和 Playwright。之後每次批改只需要開啟 NKNUBLOCK 和這個工具，約 2 分鐘就能開始。

📋
開始前需要準備： Windows 電腦、已安裝 NKNUBLOCK 並能在瀏覽器開啟、學生 .sb3 作品檔

第一部分：安裝 Python 與相關套件

1

下載並安裝 Python

前往 python.org/downloads，下載 3.11 以上版本，執行安裝程式。

⚠️ 安裝時有一個選項非常重要：「Add Python to PATH」 務必勾選，否則之後的步驟會失敗。
2

下載程式碼，安裝套件

將程式碼資料夾放到你熟悉的位置（例如桌面），開啟命令提示字元，切換到該資料夾，輸入：

pip install -r requirements.txt playwright install chromium
安裝需要幾分鐘。Playwright 會下載一個獨立的 Chromium 瀏覽器供自動化使用，約 150MB。

第二部分：啟動系統

3

先啟動 NKNUBLOCK

用平常的方式開啟 NKNUBLOCK，確認瀏覽器可以看到模擬面板（點燒杯圖示展開）。系統預設 NKNUBLOCK 執行在 http://127.0.0.1:4443。

這個步驟必須在啟動批改工具之前完成。NKNUBLOCK 關掉或網址不對，後續的批改就無法進行。
4

啟動批改工具

在命令提示字元輸入：

python app.py

看到以下訊息代表啟動成功：

* Running on http://127.0.0.1:5000
這個黑色視窗要保持開著。之後每次使用重複步驟 3–4 即可。
5

在瀏覽器開啟操作介面

打開 Chrome 或 Edge，輸入：

http://127.0.0.1:5000

你會看到設定頁面。

第三部分：設定並執行批改

6

設定頁：填入基本資訊

設定頁有幾個欄位：

  • 教具名稱：輸入教具型號前半段，例如 5016B，系統會自動比對
  • 執行等待秒數：點綠旗後等幾秒再截圖（預設 30 秒，視作品複雜度調整）
  • 搖桿座標：第一次需填入，填完後固定不需再改（見下方說明）
7

設定搖桿座標（一次性設定）

搖桿偵測需要知道模擬搖桿在螢幕上的位置。在設定頁點「自動偵測搖桿座標」，系統會嘗試自動找到位置並截圖標記。

若自動偵測失敗，可手動取得：按 F12 開啟開發者工具，切換到 Console，輸入下方指令，然後點搖桿灰色圓圈中心，記下顯示的 X、Y 數字。

document.addEventListener('click', e => console.log(e.clientX, e.clientY), {"{"}once:true{"}"})
搖桿座標偵測截圖（待補）
8

上傳學生作品

有兩種方式：

  • 直接上傳 .sb3 檔案：拖曳或選取，檔名即為學生姓名
  • 指定資料夾路徑：輸入存放所有 .sb3 的資料夾路徑，系統自動掃描全部
建議把班級作品統一放在一個資料夾，用方式②批次處理。檔名格式建議為「成績601-猴子-01 陳小明」方便後續匯出時自動對應班級座號。
9

執行頁：即時觀看進度

按「開始批改」後，自動跳到執行頁。頁面會即時顯示：

  • 目前處理到第幾位學生（進度條）
  • 正在執行的作品名稱
  • 每個步驟的詳細 log（初始化、執行、各項偵測結果）
執行進度頁面截圖（待補）
10

結果頁：查看截圖與匯出成績

批改完成後跳到結果頁，顯示所有批改記錄的表格。每筆記錄包含：

  • 學生姓名、教具、執行秒數
  • 六個評分項目的判定結果（OK / L / —）
  • 作品截圖（點縮圖可放大查看）

勾選記錄後可「匯出選取」，或直接「全部匯出」成 Excel 成績單。Excel 會自動依班級座號排序，並計算每位學生的總分。

遇到問題？

常見疑問

連線逾時，批改沒辦法開始？

最常見原因是 NKNUBLOCK 未啟動，或模擬面板沒有展開（需先點燒杯圖示）。確認 NKNUBLOCK 在瀏覽器的 http://127.0.0.1:4443 可以正常開啟後再試。

燈光顯示 L 而不是 OK？

學生程式有點亮燈條，但沒有熄滅的積木。若確認邏輯上應該要亮再滅，可能是積木名稱設定問題；若學生本來就沒有熄燈，L 就是正確結果（部分完成）。

搖桿顯示 —，但學生的程式看起來有寫搖桿控制？

可能是作品裡用到的 Scratch 變數名稱不在偵測清單裡。看執行頁 log 的「初始變數：{...}」，找有沒有搖桿相關的變數名稱，再更新系統設定。

換了新教具型號，很多項目變成 —？

不同教具使用的積木名稱可能不同（例如蜂鳴器的積木名稱從 NKNU_SetBuzzer 改成其他名稱）。看 log 的「NKNU 呼叫：[...]」，找到新的積木名稱後，更新 playwright_runner.py 開頭的關鍵字清單。

Excel 的班級座號欄位是空的？

系統依照「成績601-猴子-02鍾岩希」這樣的格式自動解析班級座號。如果檔名格式不同，匯出時可以在「無法解析」的欄位手動填入，或先統一重新命名 .sb3 檔案。

資安確認

學生資料安全嗎？

🔒
學生作品和成績完全不離開你的電腦。 這個工具不使用任何外部 API，不需要 Gemini、OpenAI 或其他雲端服務。所有處理都在本機完成。
✓ 無任何外部 API 金鑰，不需要 Gemini 或其他帳號
✓ 學生 .sb3 作品在本機執行，不上傳任何伺服器
✓ 截圖和成績存在本機 SQLite 資料庫，不同步雲端
✓ 資料庫寫入使用參數化查詢，不受 SQL 注入影響
✓ 上傳檔名經過 secure_filename() 清理，防止路徑穿越攻擊
✓ 前端所有動態插入的學生姓名、檔名均以 escHtml() 跳脫，防止 XSS
✓ 系統只在 127.0.0.1 監聽（debug=False），外網無法存取
△ 建議將 .db 資料庫檔案加入 .gitignore（若有版本控制）
